# Implementation Plan: Sports For Life Academy MVP Registration App

**Branch**: `001-registration-app-mvp` | **Date**: 2026-06-06 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-registration-app-mvp/spec.md`

## Summary

A Flutter mobile app (Android + iOS) that replaces paper-based player registration at Sports For
Life Academy. Parents scan a universal QR code, select their branch, fill in a 4-section
step-by-step wizard form in Arabic (default, RTL) or English (LTR), review their entries, and
submit to the Academy Management System via REST API. The app enforces connectivity gating,
preserves form data on submission failure, shows a copyable reference number on success, and
clears all data from device memory after successful submission.

## Technical Context

**Language/Version**: Dart 3.x — Flutter SDK 3.x

**Primary Dependencies**:
- `flutter_localizations` + `intl` — bilingual ARB-based localization, RTL/LTR support
- `dio` — HTTP client with interceptors (API key injection) and 30-second timeout
- `connectivity_plus` — network availability check at launch and on "Start Registration"
- `riverpod` — in-memory form state management (preserves data across wizard screens and retries)
- `flutter_dotenv` or `dart-define` — compile-time API key injection

**Storage**: None — form state is in-memory only (Riverpod). Cleared after successful submission.

**Testing**: `flutter_test` (unit + widget tests), `integration_test` (end-to-end flow)

**Target Platform**: Android 6.0+ (API 23), iOS 14.0+

**Project Type**: Mobile app — single Flutter project

**Performance Goals**:
- Welcome Screen visible within 3 seconds of launch on standard mobile data
- AMS submission response received within 30 seconds; timeout triggers retry screen
- Full registration journey completable in under 5 minutes

**Constraints**:
- No local data persistence after successful submission (constitution Principle III)
- All AMS communication over HTTPS (constitution Principle III)
- Static API key in every AMS request header (`X-API-Key`) (spec FR-016)
- Arabic RTL is the default language; switch only allowed on Welcome Screen (spec FR-019)

**Scale/Scope**: Single parent session per run, 10–20 branches, no in-app concurrency
